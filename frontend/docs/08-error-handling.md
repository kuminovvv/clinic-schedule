# 08. Обработка ошибок

## Общий принцип

Ошибки должны быть:

- явными;
- различимыми по типу;
- полезными для пользователя;
- полезными для отладки.

## API и запросы

Если используется `fetch`, нужно:

- проверять `response.ok`;
- формировать понятную ошибку;
- не проглатывать причину без необходимости.

## UI feedback

Если в проекте уже используется `toast`, агент должен следовать этому паттерну.

Нужно различать:

- transport error;
- API error;
- validation error;
- unsupported state.

## Логирование

`console.error` допустим, если:

- это помогает отладке;
- сообщение не дублирует UI буквально;
- ошибка не скрывается полностью.

## Комментарии

Комментарии должны объяснять `почему`, а не пересказывать код.
