# 07. Производительность

## 1. Параллельные запросы (Promise.all)

Независимые асинхронные операции должны выполняться параллельно. Это касается как серверных компонентов (RSC), так и клиентских запросов.

```tsx
// ❌ Медленно: последовательные запросы (Waterfall)
const channel = await fetchChannel(slug);
const posts = await fetchPosts(slug);

// ✅ Быстро: параллельные запросы
const [channel, posts] = await Promise.all([
  fetchChannel(slug),
  fetchPosts(slug)
]);
```

## 2. Мемоизация

Не оптимизируйте код преждевременно. Используйте мемоизацию только тогда, когда это приносит реальную пользу.

### useMemo — для дорогих вычислений:
Используйте `useMemo` только для тяжелых операций над массивами/объектами или сложных математических расчетов.

```tsx
// ✅ Правильно: фильтрация и сортировка большого массива
const filteredItems = useMemo(() => {
  return items
    .filter(item => item.isActive)
    .sort((a, b) => b.score - a.score);
}, [items]);

// ❌ Избыточно: простые операции
const doubledScore = useMemo(() => score * 2, [score]);
```

### useCallback — для сохранения ссылочной идентичности функций:
Используйте `useCallback` для обработчиков, которые передаются в качестве пропсов в дочерние компоненты (чтобы избежать лишних перерендеров дочерних элементов).

```tsx
// ✅ Правильно: функция передается в дочерний компонент
const handleSelectAction = useCallback((id: string) => {
  onSelectAction(id);
}, [onSelectAction]);

return <ItemCard onSelectAction={handleSelectAction} />;
```

## 3. Стабильные константы вне компонента

Самый дешевый способ мемоизации — вынесение статических данных за пределы рендера:

```tsx
// ✅ Правильно: массив не создается заново при каждом рендере
const DEFAULT_TAGS = ['здоровье', 'наука'];

export const TagSelector = () => {
  return <Selector defaultTags={DEFAULT_TAGS} />;
};
```

---

## 4. Каскадные `useEffect` — антипаттерн

Избегайте цепочек из нескольких `useEffect`, где один эффект меняет стейт, вызывая срабатывание другого. Это приводит к лишним циклам рендеринга и усложняет отладку.

```tsx
// ❌ Каскад (A -> B -> C)
useEffect(() => { setB(computeB(a)); }, [a]);
useEffect(() => { setC(computeC(b)); }, [b]);

// ✅ Правильно: вычислить все значения за один проход или через useMemo
const b = useMemo(() => computeB(a), [a]);
const c = useMemo(() => computeC(b), [b]);
```

---

## 5. Оптимизация импортов и бандла

* **Импорт библиотек**: Избегайте импорта всей библиотеки целиком, если вам нужны только отдельные утилиты.
  ```ts
  // ❌ Запрещено
  import _ from 'lodash';
  
  // ✅ Правильно
  import debounce from 'lodash/debounce';
  ```
* **next/dynamic**: Лениво загружайте тяжелые клиентские компоненты (графики, интерактивные редакторы, модальные окна), которые не требуются при первоначальной загрузке страницы.

---

## 6. Виртуализация длинных списков

При рендере списков размером более 100 элементов используйте виртуализацию (например, `@tanstack/react-virtual`), чтобы рендерить в DOM только видимые на экране элементы.

---

## 7. Чеклист производительности

### Критично (проверять всегда):
- [ ] Все независимые асинхронные запросы обернуты в `Promise.all` (или распараллелены).
- [ ] Отсутствуют каскадные `useEffect`.
- [ ] Тяжелые клиентские компоненты подключаются через `next/dynamic`.
- [ ] Нет импортов полных библиотек (используются точечные импорты или настроен `optimizePackageImports`).

### Важно:
- [ ] Дорогие вычисления обернуты в `useMemo`.
- [ ] Коллбэки, передаваемые в пропсы дочерних компонентов, мемоизированы через `useCallback`.
- [ ] Статические массивы/объекты вынесены в константы вне рендера.
- [ ] Частые события (поиск, скролл, resize) обрабатываются с `debounce` или `throttle`.
