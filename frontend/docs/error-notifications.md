# Уведомления и ошибки

Для всех действий пользователя применяется **shadcn/ui Toast (Base UI)**. Один `Toaster` находится в корневом `app/layout.tsx`.

## Архитектура

- `src/shared/ui/shadcn/toast.tsx` — презентационный слой Base UI, общая очередь и позиция уведомлений.
- `src/shared/lib/notifications.ts` — понятные успехи, предупреждения и ошибки, подавление одинаковых уведомлений на 3,5 секунды.
- `src/shared/api/backend-client.ts` — единая точка клиентских GET/POST/PUT/DELETE. Проверяет HTTP-статусы и автоматически вызывает уведомление об ошибке, после чего повторно выбрасывает типизированную ошибку.
- `src/shared/api/error-messages.ts` — централизованный перевод кода/причины API и контекста действия в заголовок и подсказку пользователю.
- `src/app/error.tsx` — доступный экран на случай ошибки при серверной загрузке целой страницы; клиентские toast-сообщения не могут заменить этот экран.
- `notify.constraint` — предупреждение об ограничениях курса (янтарное, 15 секунд). Такие сообщения не занимают место над формой.
- `notify.confirmConstraint` — предупреждение, которое нельзя пропустить автоматически: содержит список ограничений и кнопку «Продолжить». До нажатия расписание не создаётся. При изменении назначений уведомление закрывается и предпросмотр требуется повторить.

## Правила для новых функций

```tsx
import {sendBackendRequest, getClientData} from "@/shared/api/backend-client"
import {notify} from "@/shared/lib/notifications"

// Ошибка запроса автоматически становится уведомлением; не показывайте её ещё раз вручную.
const appointments = await getClientData<Appointment[]>("/v1/appointments?from=...&to=...")
await sendBackendRequest("/v1/calendar-settings", "PUT", settings)

// Для успешного явного действия:
notify.success("Запись сохранена", "Она появилась в календаре.")

// Для запрета, выявленного до обращения к API:
notify.warning("Это время занято", "Выберите свободное время или другой день.")

// Для ограничения, найденного в предварительном расчёте:
notify.constraint("Не все сеансы помещаются в курс", "Уменьшите количество сеансов или измените срок пребывания.")
```

**Не показывать пользователю** HTTP-коды, внутренние названия сервисов, английские тексты серверных ошибок, названия таблиц и технические исключения. Сообщение должно объяснять причину и следующий шаг. Для блокирующих ошибок, после которых требуется действие (например, обновление изменённого в другой вкладке плана), сохраняется доступная кнопка прямо на странице.

Сетевые проблемы, серверные ошибки, конфликты, неверные данные и ограничения курса имеют отдельные сообщения. Подробная причина API сохраняется в `BackendRequestError` для диагностики, но не выводится напрямую на экран.

Ожидаемые проверки:

```powershell
python scripts/check-error-notifications.py
python scripts/check-course-notifications.py
node --experimental-strip-types scripts/check-error-messages.mjs
```

Первый скрипт проверяет браузер с локально запущенным фронтендом. Запросы с ошибками подменяются внутри браузера; данные приложения не изменяются.
