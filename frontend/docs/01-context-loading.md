# 01. Загрузка контекста

## Принцип

Контекст должен быть достаточным, но не избыточным.

Агент не должен:

- заранее читать весь репозиторий;
- тащить в контекст неиспользуемые файлы;
- решать по памяти, если можно быстро прочитать код.

## Что читать сначала

Перед изменениями:

1. Точку входа задачи
2. Ближайшие `types.ts`
3. Публичный API через `index.ts`
4. Места использования
5. `tasks/todo.md`
6. `tasks/lessons.md`

## Как расширять контекст

Разрешенная стратегия:

- идти от конкретного вызова;
- поднимать только зависимые слои;
- не читать соседние несвязанные модули.

## Источники истины

В порядке приоритета:

1. Код
2. Типы
3. Тесты
4. `tasks/todo.md`
5. `tasks/lessons.md`
6. Комментарии

Если документация расходится с кодом, приоритет у кода, кроме задач сознательной миграции к новой модели.
