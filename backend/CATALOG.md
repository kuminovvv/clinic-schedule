# Каталог процедур

`GET /v1/procedures` возвращает каталог в порядке `position, id` и его
версию в заголовке `ETag`. Список и версия читаются из одного снимка БД.

`PUT /v1/procedures` и `DELETE /v1/procedures/{id}` требуют `If-Match`
с последним полученным ETag. Без заголовка API возвращает 428, с неверным
форматом — 400, с устаревшей версией — 409. Успешная запись возвращает новый
ETag; запись неизменённых значений не увеличивает версию.

PUT атомарно добавляет и обновляет переданные процедуры. Отсутствующие
в массиве строки не удаляются: для удаления используется DELETE.
Позиции переданных процедур определяются порядком массива. Интерфейс
передаёт весь текущий каталог и объединяет быстрые изменения полей.

Все изменения каталога должны проходить через API. При вынужденной ручной
правке БД необходимо в одной транзакции взять блокировку
`LOCK TABLE procedures IN SHARE ROW EXCLUSIVE MODE`, изменить данные
и увеличить `procedure_catalog_revision.revision` для `id=1`. Прямая
правка SQL без обновления версии обходит защиту от устаревших снимков.
Начальное заполнение при запуске API соблюдает этот же порядок.

Запись использует `pgx.Batch`, а `IS DISTINCT FROM` исключает обновление
неизменённых строк. Индексы миграции 016 поддерживают проверки ссылок
при удалении. Фактическое время запросов на больших данных нужно оценивать
через `EXPLAIN (ANALYZE, BUFFERS)` на репрезентативной копии базы.
